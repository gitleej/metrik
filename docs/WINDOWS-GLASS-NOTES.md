# Windows 玻璃材质：实测结论与未完成项

小组件与胶囊条在 Windows 上的三档玻璃配色（深色 / 浅色 / 透明）踩过很多坑，
其中几条与直觉相反。这份文档记录**已经用实验证伪或证实的事实**，避免下一次
再从头试一遍。所有结论都在 Windows 11 26200、单显示器 2560×1440、系统缩放
125% 上实测得到。

## 1. 系统材质在这台机器上给不出真透明

| 路径 | API | 实测结果 |
|---|---|---|
| SWCA Acrylic | `SetWindowCompositionAttribute` + `ACCENT_ENABLE_ACRYLICBLURBEHIND` | **调用返回成功，渲染成实心板**。传深色 tint 也渲染成白色，说明 tint 被忽略 |
| DWM 系统背板 | `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW` | 调用成功，无可见变化 |
| HostBackdrop | `ACCENT_ENABLE_HOSTBACKDROP` + `CreateHostBackdropBrush` | 有材质感，但近乎不透明（Mica 系） |
| 逐像素透明 | `DwmEnableBlurBehindWindow`（空区域，tao 建窗时用的手法） | 重新装一遍无效 |

**判别实验**：把外壳、`#root`、`body`、`html` 以及全部子元素的背景清成
`transparent`，关掉原生背板，再把 WebView2 底色设为全透明，最后把窗口挪到高
对比度壁纸上——窗口**仍然渲染成一块实心白**。用"窗口在 / 窗口挪走同区域像素
比对"这种不依赖背景的判据复核：平均差 232、最大差 750，即两张图内容完全不同。

**结论：WebView2 的合成表面在这台机器上不透明，任何垫在它后面的系统材质都看
不见。** 系统的"透明效果"开关是开着的（`EnableTransparency=1`），不是这个原因。

## 2. 因此透明档不走系统材质，改自绘

参考实现是桌面挂件 Pogget。它的官方 PDB 里有 `g_WallpaperD2DCache`、
`WallpaperCacheItem`、`RegisterWallpaperChangeNotification1`、`CGaussBlurFilter`、
`CLSID_D2D1GaussianBlur`、`VinaFluidMaterial::Render`，导入表里有
`SystemParametersInfoW`、`BitBlt`、`PrintWindow`。

**它的"透明"是画出来的**：取桌面壁纸 → 高斯模糊 → 缓存 → 按窗口屏幕位置画出
对应区域 → 叠白 tint + 深色文字。只透壁纸，不透背后的窗口。

Metrik 的透明档照此实现：后端 `get_glass_wallpaper` 取壁纸、裁剪、模糊、缓存
并回传 data URL，前端按窗口客户区坐标做负偏移贴在外壳背景上。

## 3. 已知坑

- **必须用 `innerPosition()`，不能用 `outerPosition()`。** 窗口外框比 WebView
  视口大（竖条实测 90 逻辑 px 的窗口里只有 76px 是网页），用外框坐标取景会整
  体偏移几像素。
- **壁纸幻灯片必须监听。** 换图后不重取，取景就和真实桌面对不上。现在靠轮询
  廉价指纹（路径 + mtime）发现变化。
- **壁纸采样层的不透明度要给满。** 调低它露出来的不是桌面，而是窗口那层不透明
  白底，反而更实。
- **浓度滑杆按配色分两条曲线。** 透明档铺的是磨砂壁纸，罩层可以归零；深色/浅色
  档铺的是半透明色板，低于 0.55 就压不住底下的不透明白，会出现白底白字。滑杆
  行程 5%–95% 对透明档映射到 0.05–0.95，对深色/浅色映射到 0.55–0.96。

## 4. 未完成：取景垂直偏移 27px

**现象**：透明档的取景与真实桌面在垂直方向差约 27 物理像素，水平方向准确。

**测量方法**：把生成的磨砂底图与真实屏幕截图做同样模糊，在确认无遮挡的纯壁纸
区域上做二维互相关，扫 ±96px。（第一轮样本区落在 Pogget 面板上——它自己也贴着
模糊壁纸，会假性吻合，必须排除。）

右下角沙丘（纯壁纸、纹理丰富）的结果：

| 偏移 | 平均差异 |
|---|---|
| dx=0, dy=0（现状） | 34.58 |
| dx=0, dy=−27 | **6.04** |

另外两块样本给出 dy = −26 / −27，dx 全部为 0。**是常量偏移，不是缩放错误。**

**原因**：我们的做法是读壁纸文件后自己复刻 Windows 的"填充"裁剪（3840×2400
缩到 2560×1600，上下各裁 80 行）。按测量结果反推，Windows 实际从第 53 行开始
裁，不是居中的 80 行。再拿原图直接扫 Windows 的真实裁剪位置，三块样本给出
110 / 115 / 12，差异值全在 27–34 徘徊，**没有任何偏移能对上**。

**结论：复刻 Windows 的裁剪规则这条路本身是错的**，它画壁纸时不只是几何裁剪。

**下一步（未做）**：改为直接抓取渲染后的壁纸——找到承载壁纸的 shell 窗口
（`Progman` / `WorkerW`），用 `PrintWindow` 抓它的内容。Pogget 导入 `BitBlt` /
`PrintWindow` 正是这个做法。这样不需要任何裁剪数学，并且自动覆盖填充/适应/
平铺/跨屏各种壁纸模式、多显示器、不同 DPI 与幻灯片换图。

## 5. 关于"还是不如 Pogget 透"

浓度拖到最低时白 tint 已经是 0、模糊降到最低，贴的就是壁纸本身——**这套方案的
透明度已经到顶**。剩下的观感差距不在透明度，在前景的视觉重量：Pogget 是线条
图标 + 细字 + 极淡分隔；Metrik 是实心方形 App 图标 + 粗体百分比 + 饱和进度条。
同样的透明底，前景越重看上去越实。这是设计问题，不是材质问题。

## 6. 平台边界

以上全部只适用于 Windows。macOS 面板材质跟随系统 vibrancy，设置页不提供玻璃
配色选项；透明档的壁纸磨砂管线在 macOS 上不启用。
